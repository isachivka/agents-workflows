# A start over max_runs waits in line — plan

Spec: [2026-10-07-run-queue-design.md](../specs/2026-10-07-run-queue-design.md). One commit.

1. `src/types.ts`: status `queued`; `RunState.queuedEvent`, `queuePos`; input `{kind: "queued"}`.
2. `src/engine.ts`: `start` on a queued run sets it running; `queued` records the place and types
   `queueText` to bound roles only; `ordinal`.
3. `src/daemon.ts`: `startRun` queues instead of refusing (cron and `flow.trigger.skipped` starts
   still refused, only cron records the skip); `startQueued()` after every apply, at init and on
   reload; `RunSummary.queue`; `resolveTarget` explains a queued run.
4. `src/cli.ts`: `flow start` prints the place; `flow ls` shows it. `ui/text.js`: queued state.
5. Tests: daemon (queue, start on stop, place notice, cron skip), CLI, HTTP, UI text. A guard in
   `test/daemon-helpers.ts` fails a test past 5000 events, so a self-feeding loop cannot fill the
   disk again.
6. Docs: processes.md, cli.md, concepts.md, troubleshooting.md, http-api.md, both skills.
